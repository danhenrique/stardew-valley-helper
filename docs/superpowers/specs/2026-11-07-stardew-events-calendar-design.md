# Stardew Helper: events and calendar (design)

Date: 2026-11-07 · Branch: `feat/stardew-valley-helper`

## Goal

Give the player one place to **look up** what happens on each in-game day: festivals, birthdays, the
last day to plant a crop, and foraging events. The home page shows a summary, `/calendario` shows
everything, and `/eventos` and `/eventos/$id` show the details.

## Scope and decisions

- **Read-only.** No marking events as done, no reminders, no custom events. No new per-player state,
  no new table, no new endpoint.
- Fixed events repeat every year (they have no year). The reference date is `profile.currentDate`.
- The event list is **built in the browser** (`lib/events.ts`) from data the API already serves.
  Rejected alternatives: a `GET /events` endpoint (new contract with no gain, since the data is small
  and static) and static JSON bundled in the website (duplicates the source of truth).
- Foraging events are included now (3 records) so the calendar is complete, as in the scheduler.
- UI labels stay in Portuguese (pt-BR); code, docs and commits are in English.

## 1. Data

### game-data (`/home/danhenrique/projects/stardew-valley/game-data`)

- New folder `data/eventos-coleta/` with 3 files: `salmonberry-season` (spring 15-18),
  `summer-beach-foraging` (summer 12-14), `blackberry-season` (fall 8-11).
- Fields: `id`, `type` (= `eventos-coleta`), `name` (en, pt-BR), `nameVerified: false`, `season`,
  `startDay`, `endDay`, `item` (`salmonberry`, `clam`, `blackberry`, only if the id exists in the
  game data).
- Generated by `scripts/build-data.py` from the scheduler's values (`src/lib/events.ts`, which come
  from the wiki). The JSON files are never edited by hand.
- `data/README.md` is not regenerated by the script, so add the new folder to its folder table by hand.

### DynamoDB (`packages/stardew-valley/db`)

- New `ForagingEvent` entity modelled on `Festival`: `PREFIX/SK = "FORAGING_EVENT"`,
  `FOLDER = "eventos-coleta"`, fields `season`, `start_day`, `end_day`, `item`.
- Register it in `entities/__init__.py` and `importer/convert.py`.
- Re-import the data into the prod environment with the existing import flow.

### API (`packages/stardew-valley/api`)

- `game_data.py`: map `"eventos-coleta": ("FORAGING_EVENT", "FORAGING_EVENT")`.
- `PlantableOut` gains `lastPlantingDay: int | None` (null for fruit trees). This is the only contract
  change; regenerate the website client afterwards.
- A crop has one `lastPlantingDay` shared by all its seasons, so a multi-season crop gets the same day
  in each season.

## 2. Website (`packages/stardew-valley/website`)

### `lib/events.ts` (pure, tested)

- `FixedEvent`: `kind` (`festival | birthday | cropDeadline | foraging`), unique `id`, `season`, `day`,
  `endDay?`, and a reference to the source entity.
- `buildEvents({ festivals, villagers, plantables, foraging })`:
  - festival: `startDay` / `endDay`;
  - birthday: `villager.birthday`;
  - crop deadline: one event per season the crop grows in, on `lastPlantingDay`;
  - foraging: `startDay` / `endDay`.
- `eventsOn(events, season, day)` (includes every day of a multi-day event),
  `eventsInSeason(events, season)`, `upcomingInSeason(events, today)` (today through day 28 of the
  current season).
- Event ids, also used in the detail route: `festival:flower-dance`, `birthday:abigail`,
  `foraging:blackberry-season`, `cropDeadline:parsnip-seeds:spring`.

### `useFixedEvents()` hook

`listGameEntities` for `festivais`, `personagens` and `eventos-coleta`, plus `usePlantables`;
`staleTime: Infinity`; returns the list from `buildEvents`.

### Routes and navigation

- `/calendario`: 4-week x 7-day grid per season with previous/next navigation (based on
  `HarvestCalendar` and Tailwind Plus `02-month-view`). Markers per kind (colour and Heroicons icon),
  filters by kind. Selecting a day shows its details below the grid, linking to `/eventos/$id`. Also
  shows the player's harvests (`plantings.schedule.harvests`).
- `/eventos`: list grouped by season, with a kind filter and name search.
- `/eventos/$id`: detail. Festival: days and whether shops close. Birthday: who, marriageable, loved
  gifts (`gifts.loves`, names via i18n). Crop deadline: the seed, growth days and last planting day.
  Foraging: the item and the day window.
- Home (`/`): "Próximos eventos" card above the plantings, using `upcomingInSeason`, with **festivals,
  birthdays and foraging events only** (crop deadlines stay in the calendar, they would be too many).
  Today's events come first; birthdays are grouped; a "Ver calendário" link.
- `NAVIGATION` gains "Calendário" and "Eventos".

### Style and project rules

Tailwind with light and dark themes; Heroicons; icon-only buttons have `aria-label` and `title` in
Portuguese. Before building each component, look for an equivalent in
`/home/danhenrique/projects/.tailwind/`; if there is none, ask the user how to proceed.

## 3. Tests

- Unit, `lib/events.ts`: day 28, multi-day event, season rollover, crop without `lastPlantingDay`,
  unique ids.
- Component: calendar, list, detail and home card (empty, loading and error states).
- API/db: `ForagingEvent` entity and importer; `PlantableOut` exposes `lastPlantingDay`.

## 4. Out of scope

Marking events as done, reminders, custom events, a `/events` endpoint, and events that depend on
player progress (heart-event cutscenes, etc.).
