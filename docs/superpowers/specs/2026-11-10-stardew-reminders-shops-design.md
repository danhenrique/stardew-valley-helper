# Stardew Helper: weekly reminders and shop hours (design)

Date: 2026-11-10 · Branch: `feat/stardew-reminders-shops` (on top of `feat/stardew-today-events`, PR #7)

## Goal

Tell the player what else matters **today** besides plantings, machines and fixed events: recurring
reminders (Traveling Cart, Krobus, Desert Trader, Queen of Sauce, special orders, weekly foraging,
new season) and which shops are open or closed. The home "Hoje" card shows today's reminders and the
shops closed today; a new `/lojas` page shows every shop with today's status and hours.

Reference: the scheduler at `/home/danhenrique/projects/stardew-valley/game-data/.tmp/stardew-valley-scheduler`
(`src/data/reminders.ts`, `src/lib/reminders.ts`, `src/data/shopSchedule.ts`).

## Scope and decisions

- **In scope:** weekly reminders, the new-season reminder, shop hours/status.
- **Out of scope:** the scheduler's daily reminders (weather, animals, farm cave, hardwood, help wanted,
  crab pots, fish ponds), festival-prep countdowns, marking reminders as done, rain as player state,
  shop prices/offers, reminders in "Próximos eventos" or the calendar.
- **Data source:** the existing pipeline, `game-data` → DynamoDB → API → website (approach A).
  Rejected: deriving reminders from shop offers (does not cover Queen of Sauce, special orders,
  foraging or the new season) and expanding reminders into dated records at import (bloats the table
  and the calendar).
- **Player progress** lives in the profile: Community Center restored, Key to the Town, Ginger Island
  boat repaired. Rain is not stored; rain-dependent shops show a note.
- The in-game week starts on Monday: day 1, 8, 15 and 22 are Mondays.
- UI labels stay in Portuguese (pt-BR); code, docs and commits are in English.

## 1. Data

### game-data (`/home/danhenrique/projects/stardew-valley/game-data`)

New folder `data/lembretes/`, one JSON per reminder, generated by `scripts/build-data.py` from the
scheduler's `src/data/reminders.ts` and `messages/{en,pt-BR}.json` (`reminders.<id>.title/detail`).
The JSON files are never edited by hand; `data/README.md` gains the folder in its table by hand.

Fields: `id`, `type` (= `lembretes`), `name` (en, pt-BR), `nameVerified: false`, `detail` (en, pt-BR),
`trigger`, optional `nightMarketDaily`, optional `suppressOnFestival`.

| id | trigger | flags |

| `traveling-cart` | `{ kind: "weekly", weekdays: ["fri", "sun"] }` | `nightMarketDaily: true` |
| `krobus-sprinkler` | `{ kind: "weekly", weekdays: ["fri"] }` | `suppressOnFestival: true` |
| `desert-trader-staircase` | `{ kind: "weekly", weekdays: ["sun"] }` | |
| `queen-of-sauce-new` | `{ kind: "weekly", weekdays: ["sun"] }` | |
| `queen-of-sauce-rerun` | `{ kind: "weekly", weekdays: ["wed"] }` | |
| `special-orders` | `{ kind: "weekly", weekdays: ["mon"] }` | |

`special-orders` is Monday only: the scheduler shows it every day until marked done, and this app has

### DynamoDB (`packages/stardew-valley/db`)

- New `Reminder` entity modelled on `Festival`: `PREFIX/SK = "REMINDER"`, `FOLDER = "lembretes"`,
  fields `detail` (`LocalizedText`), `trigger` (`MapAttribute`), `night_market_daily` and
  `suppress_on_festival` (`BooleanAttribute`, null). Register it in `entities/__init__.py` and
  `importer/convert.py`.
- `Player` gains `community_center_restored`, `key_to_town`, `boat_repaired`
  (`BooleanAttribute(default=False)`, camelCase `attr_name`). Existing records read as `false`; no
  migration.
- `Shop` is unchanged (`schedule` is a free map, so `dateHours` needs no model change).
- Re-import the data into prod with the existing flow (`import --dry-run`, then `import`).

### API (`packages/stardew-valley/api`)

- `game_data.py`: `"lembretes": ("REMINDER", "REMINDER")`, served by the generic `/game/lembretes`.
  No new endpoint.
- `ProfileIn` / `ProfileOut` gain `communityCenterRestored`, `keyToTown`, `boatRepaired`
  (`bool = False`), read and written by `/me`. This is the only contract change; regenerate the
  website client afterwards.

## 2. Website logic (`packages/stardew-valley/website/src/lib`, pure and tested)

### `lib/gameDate.ts`

- `weekdayOf(day)`: `['mon','tue','wed','thu','fri','sat','sun'][(day - 1) % 7]`.

### `lib/events.ts`

- Festival `FixedEvent` gains `shopsClosed?: boolean`, read from the festival attributes in
  `buildEvents`.

### `lib/reminders.ts`

- `Reminder` type parsed from `GameEntityOut` (invalid records are dropped, like `buildEvents`).
- `remindersToday(reminders, events, today)`, in data order:
  - `weekly`: today's weekday is in `weekdays`; with `nightMarketDaily`, also every day of winter
    15–17.
  - `seasonStart`: day 1.
  - `suppressOnFestival`: dropped when a festival with `shopsClosed: true` covers today.

### `lib/shops.ts`

- `Shop` type parsed from `GameEntityOut` (`schedule`, `scheduleText`); shops without `schedule`
  (casino, Qi's Walnut Room, sewers) are dropped.
- `ShopProgress = { communityCenterRestored, keyToTown, boatRepaired }`.
- `shopStatusToday(shop, today, events, progress)` returns
  `{ status: 'open' | 'closed', hours: string[], reason?: string, notes: string[] }`.
- Closed, first match wins:
  1. `closesPermanentlyAfterCommunityCenter` and Community Center restored → "Fechada definitivamente".
  2. `openSeasons` without today's season → "Fora de temporada".
  3. A festival covering today with `shopsClosed` and `festivalClosure: "all"` → "Festival".
  4. Today in `closedDates` → "Fechada hoje".
  5. Today's weekday in `closedDays`, or in `closedDaysBeforeCC` / `closedDaysAfterCC` by Community
     Center → "Fecha às <dia>".
- `dateHours` for today overrides rules 2–5 and the hours (Traveling Cart at the Night Market).
- Hours: `weekdayHours[weekday]`, else `hoursAfterBoatRepair` when the boat is repaired, else
  `hoursWithKeyToTown` when the player has the key, else `hours`. Formatted as `9:00–17:00`; `(+1d)`
  closes as `2:00`.
- Notes (no state): `closedIfRain` → "Fecha se chover"; `openIfRainOnly` containing today's weekday →
  status closed with "Abre se chover"; `festivalClosure: "some"` → `scheduleText.festival` (pt-BR).
- `closedToday(shops, today, events, progress)`: closed shops for the "Hoje" notice, leaving out
  "Fora de temporada" and "Fechada definitivamente".

## 3. Screens

### Profile (`TodayBar`, "Alterar" panel)

- Three `Toggle`s below "Profissão Agricultor": "Centro Comunitário restaurado", "Chave da Cidade",
  "Barco para a Ilha Gengibre consertado", each with a one-line description. Saved by "Salvar".
- "Dia anterior" / "Avançar dia" spread the whole profile instead of rebuilding it from
  `currentDate` and `agriculturist`, so the new flags are kept.

### "Hoje" card (`TodayList`)

- New **"Lembretes"** group between "Eventos" and "Plantios": one row per reminder with its Heroicons
  icon, name and detail (secondary text); no link. Icons by id in the website, fallback `BellIcon`:
  cart `ShoppingCartIcon`; Krobus and Desert Trader `BuildingStorefrontIcon`; Queen of Sauce `TvIcon`;
  special orders `ClipboardDocumentListIcon`; foraging `SunIcon`; new season `SparklesIcon`.
- Last row of the group: "Fechadas hoje: <names>" with a "Ver lojas" link to `/lojas`, when any shop
  is closed today (per `closedToday`).
- Loading or error of reminders or shops shows a notice in the group (as in "Eventos"); the group is
  hidden when there is nothing to show.

### `/lojas` (new route, in `NAVIGATION` after "Eventos")

- Heading "Lojas" with today's date. Table in a `CARD`, adapted from Tailwind Plus
  `application-ui-v4/react/lists/tables/08-with-hidden-columns-on-mobile.jsx`.
- Columns: **Loja**; **Hoje** (green "Aberta" or gray "Fechada" badge, with the reason); **Horário**
  (today's, with progress applied); **Fecha** (fixed closed weekdays, desktop only); **Observações**
  (notes plus `scheduleText.note` in pt-BR, desktop only). On mobile the hidden columns stack under
  the name, as in the component.
- Order: data order. Loading and error states like the other pages.

### Data hooks

- `useGameData`: `useReminders()` (`/game/lembretes`) and `useShops()` (`/game/lojas`), following
  `useFixedEvents`.

### Style and project rules

Tailwind with light and dark themes; Heroicons; icon-only buttons have `aria-label` and `title` in
Portuguese. Look for an equivalent in `/home/danhenrique/projects/.tailwind/` before building each
component; if there is none, ask the user.
